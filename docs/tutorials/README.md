## 前置条件

```bash
python --version        # 需要 >= 3.10
pip install pasm-framework
python -m pasm_framework doctor     # 确认环境没问题
```

`doctor` 输出全 `v` 就可以开始了。它是你最该记住的命令 ——
出问题先跑它，它会直接告诉你是哪一层坏了。

## 三个核心概念（先记住，后面都靠它们）

| 概念 | 一句话 | 类比 |
| --- | --- | --- |
| **Capability（能力）** | 明确"要做一件事"的入口，比如"退货"、"查订单" | 菜单上的按钮 |
| **DomainAdapter（领域知识）** | 注入你业务里的事实与规则 | 员工手册 |
| **Plugin（插件）** | 可选叠加的通用能力（会话/知识库/LLM/护栏/网关…） | 可插拔的外设 |

`handle(text)` 的处理顺序（记住这张图，调试会快很多）：

```
用户输入
  │
  ├─1 on_message_in   安全扫描 / 会话绑定     ← stop 就短路返回
  ├─2 能力路由        命中 Capability 就执行
  ├─3 on_retrieve     插件贡献资料（知识库检索）→ 合并进 msg.facts
  ├─4 on_reply        生成（LLM 在此产出；模板兜底在后面）
  ├─5 on_reply_final  收尾：护栏脱敏 / 温度润色  ← 唯一出口，每条路径只跑一次
  └─6 on_learn        自学习（优质问答沉淀回资料库）
       │
       ▼
     返回给用户
```

## 常见困惑

**"我改了配置但没生效？"**
配置优先级是 `preset < 文件 < 环境变量 < 代码里显式传的`。
用 `python -m pasm_framework config --preset chatbot --env` 看**最终解析结果**。

**"为什么能力没被触发？"**
关键词只在**句首 12 个字**内匹配（这是刻意的，避免长句里出现"退货"就误触发）。
"我要退货" ✅ 命中；"我昨天买的东西想了想还是想退货" ❌ 不命中 —— 改用
`predicate` 自定义判断，或把能力做成插件。

**"为什么答非所问 / 答不上来？"**
知识库是**关键词 + 中文二字词**匹配，没有语义理解。
"多久**发货**" 匹配不上 FAQ 里的 "24 小时内**发出**"（同义不同字）。
资料里尽量用用户会说的词，或开启 LLM（教程 05）。检索打分偏好**标题命中**，
所以把关键信息写进 `title` 效果最好。

**"离线能用吗？"**
能。不装任何模型、不联网，知识库 + 模板回复就足够撑起一个客服；
LLM 是"锦上添花"而非必需 —— 这是本框架和很多框架不同的地方。
